# Skiplist-CPP 3 分钟项目讲稿

## 1. 适用场景

这份讲稿适合：

1. 面试中的“请介绍一下你的项目”
2. 你已经读过代码，准备做 3 分钟左右的结构化表达
3. 你希望把它讲成“存储方向项目起点”，而不是“简单算法题实现”

## 2. 3 分钟版本

大家好，我想介绍的是一个基于 SkipList 的轻量级 KV 存储 Demo。我选择这个项目的原因是，它虽然代码量不大，但正好覆盖了存储面试里几条很核心的链路，包括内存数据结构、增删查、简单持久化、并发访问和性能压测，所以很适合拿来做源码吃透和工程化改造。

这个项目的核心实现基本都在 `skiplist.h` 里。内存结构上，它用的是典型跳表：头节点 `_header` 作为多层入口，每个节点维护一个 `forward` 指针数组。插入、查询和删除都是从当前最高层开始，先横向移动，再逐层下降。插入和删除会维护一个 `update[]` 数组来记录每层前驱，这样最后可以一次性回接指针。平均时间复杂度是 `O(log n)`。

它当前已经实现了几项基础能力。第一是插入、查询、删除和展示。第二是简单持久化，也就是 `dump_file` 会顺着第 0 层把全部有序数据按 `key:value` 写到 `store/dumpFile`，`load_file` 再逐行读回并通过 `insert_element` 重建跳表。第三是有一个 `main.cpp` 作为 demo，还有一个 `stress_test.cpp` 作为粗略压测入口。

但我对这个项目的定位不是“成熟数据库”，而是“跳表存储 Demo”。它现在最大的短板主要有四类。第一，并发模型不完整，只有插入和删除加了一把头文件全局锁，查询、遍历和落盘都是无锁的，所以严格来说并不线程安全。第二，持久化只是全量文本 dump，没有 WAL，也没有真正的崩溃恢复一致性。第三，模板接口是半泛型设计，因为 `load_file` 里把 key 直接写死成了 `stoi`。第四，工程质量上还有一些明显问题，比如递归析构、裸指针资源管理和 benchmark 被日志严重污染。

如果继续改造，我会优先做两层事情。P0 先把它做正确，包括去掉头文件全局状态、补测试、修正资源管理和接口语义。P1 再补更像存储系统的能力，比如实例级读写锁、WAL、恢复流程，以及更可信的 benchmark。这样它就能从“课程 Demo”升级成“能讲工程权衡的轻量级 KV 项目”。

所以我会把这个项目定义为：一个以跳表为核心、已经具备基础 KV 和简单落盘能力，但还在持续补齐并发、恢复和工程质量的轻量级存储引擎改造项目。

## 3. 30 秒收尾版

如果面试官只想听一句话总结，可以这样说：

1. 这是一个基于跳表的轻量级 KV Demo，已经实现了增删查和全量文本持久化。
2. 我重点不是把它包装成成熟数据库，而是把它当作存储系统训练项目，去系统补齐并发安全、持久化恢复、测试和 benchmark。
3. 我现在可以把它的核心数据路径、主要缺陷和后续改造方向讲清楚。
